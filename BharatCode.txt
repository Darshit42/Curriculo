BharatCode Build League - Round 1 submission
==============================================

Project:   Curriculo - turn any Git repository into a guided, interactive course
Track:     Learning & education
Builder:   github.com/Darshit42
Repo:      https://github.com/Darshit42/Curriculo
Model:     qwen-3.8-27b via the BharatCode API (https://bharatcode.ai/api/model/v1)

WHAT IT IS
----------
Curriculo is a CLI (plus a Claude skill) that reads a codebase and teaches it.
Point it at a repo and it produces an ordered learning path: lessons that go
from entry points to core abstractions to the parts that trip newcomers up,
each grounded in real files and line numbers, followed by quizzes written from
the actual code. It writes a LEARN.md the maintainer commits, so every future
contributor gets the course for free, and an interactive terminal UI to take it.

THE PROBLEM
-----------
Ramping onto an unfamiliar codebase takes weeks, and most of that cost is a
senior engineer answering the same questions. READMEs describe intent, not
structure; architecture docs go stale; pasting a repo into a chatbot answers
one question at a time with no path and no check that you understood.
Curriculo produces the missing artifact: an ordered walk through the code
that matters, which checks understanding at every step.

WHO IT IS FOR
-------------
- New team members joining a large codebase
- Maintainers who want onboarding docs that cost minutes, not days
- Students and self-learners studying well-known open-source projects
- First-time open-source contributors looking for the right module

TRY IT (Node.js 18+, no install, zero dependencies)
---------------------------------------------------
  export BHARATCODE_API_KEY=bc_live_...      # your own key
  npx github:Darshit42/Curriculo gen expressjs/express --learn

  npx github:Darshit42/Curriculo gen . --offline   # no key: heuristic course
  npx github:Darshit42/Curriculo learn             # resume a course anytime

HOW BHARATCODE IS USED
----------------------
Every model call goes to qwen-3.8-27b through /chat/completions, in a short
prompt chain:
  1. Repo summary + outline   - from the directory tree, README and entry points
  2. Lesson synthesis          - each lesson sees ONLY its own files' excerpts
                                 (run in parallel)
  3. Quiz generation           - multiple-choice questions checkable in the code
The model never sees the whole repo: files are ranked (entry points, import
fan-in, path heuristics) and cut to signal regions before prompting. Every
response is validated - a lesson must cite its files, quiz answers must be
valid - retried once, and degraded to a file list rather than failing a run.
reasoning_effort is set to "low", with an automatic retry when reasoning
exhausts the output budget.

MEASURED ON REAL RUNS (qwen-3.8-27b)
------------------------------------
  sindresorhus/ky       8 lessons, 16 questions   2m44s   ~62k tokens
  expressjs/express     7 lessons, 14 questions   3m54s   ~58k tokens
  pallets/click         8 lessons, 16 questions   5m15s   ~71k tokens (run alongside ky)
  Re-run on unchanged code: 0 tokens (content-hash cache), ~1 second

FEATURES
--------
- One command: local path, GitHub URL, or owner/name shorthand
- Lessons cite exact paths and line numbers; quizzes come from the code
- Committable LEARN.md that reads well on GitHub, plus a README badge
- Zero-dependency terminal UI: lesson list, open-file-in-editor, quizzes,
  saved progress and resume
- Claude skill adapter sharing the same engine and manifest format
- Offline mode with code-grounded heuristic quizzes when no key is set

PRIVACY AND SAFETY
------------------
- Honors .gitignore; never reads .env files, keys, certificates or anything
  matching credential/secret patterns
- Only ranked, truncated excerpts are sent to the model, never the full tree
- The API key is read from the environment only and is never written to the
  manifest, cache or LEARN.md
